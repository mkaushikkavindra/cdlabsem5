# Experiment 4 – Variable Validation using Lex and Yacc

## Aim

To design and implement a **Lex and Yacc program to validate whether a given input follows the specified variable grammar**.

## Objective

* Use **Lex/Flex** to identify letters and digits.
* Generate tokens for the parser.
* Use **Yacc/Bison** to check the input against a grammar.
* Display whether the entered variable is valid or invalid.

## Software Requirements

* Lex/Flex
* Yacc/Bison
* GCC Compiler
* C Programming Environment

## Files

| File            | Description                    |
| --------------- | ------------------------------ |
| `valvar.l`      | Lex/Flex source file           |
| `valvar.y`      | Yacc/Bison grammar file        |
| `lex.yy(3).c`   | C source generated by Flex     |
| `valvar.tab.c`  | C source generated by Bison    |
| `valvar.tab.h`  | Header file generated by Bison |
| `valvar.exe`    | Compiled executable            |
| `output(3).txt` | Sample execution output        |

The generated Bison header defines two application tokens: `LET` and `DIG`. 

---

## Description

This experiment uses **Lex/Flex and Yacc/Bison together** to validate a variable.

The basic process is:

```text
Input Variable
      ↓
  Lex / Flex
      ↓
  Tokens
      ↓
 Yacc / Bison
      ↓
Grammar Validation
      ↓
 ┌────┴────┐
 ↓         ↓
Valid     Invalid
```

---

## Lex/Flex

The Lex program `valvar.l` performs lexical analysis.

It recognizes:

| Input            | Token                  |
| ---------------- | ---------------------- |
| Letter           | `LET`                  |
| Digit            | `DIG`                  |
| Whitespace       | Ignored                |
| Newline          | End of input           |
| Other characters | Returned as themselves |

The generated scanner confirms that matching letters return `LET`, digits return `DIG`, whitespace is ignored, and the newline terminates parsing. 

---

## Yacc/Bison

The Yacc program `valvar.y` defines the grammar used to validate the variable.

The generated parser contains the following grammar symbols:

```text
variable
var
LET
DIG
```

and has **5 grammar rules**. 

The generated parser is a **Bison 3.8.2** parser. 

---

## Grammar

The grammar can be represented in simplified form as:

```text
variable → var

var → LET
    | LET var
    | DIG
    | DIG var
```

This means the parser builds the variable from the `LET` and `DIG` tokens according to the rules defined in the source grammar.

---

## Tokens

### `LET`

`LET` represents a letter recognized by Lex.

For example:

```text
a
b
x
A
Z
```

### `DIG`

`DIG` represents a digit.

Examples:

```text
0
1
2
5
9
```

The Bison-generated header explicitly defines:

```text
LET = 258
DIG = 259
```



---

## Example

For the input:

```text
add
```

Lex recognizes the characters as `LET` tokens.

The parser checks the resulting token sequence against the grammar.

The provided execution output shows:

```text
Enter the variable: add
Valid variable
```



Therefore, `add` is accepted by the implemented grammar.

---

## Program Flow

For an input such as:

```text
abc
```

the process is:

```text
abc
 ↓
Lex/Flex
 ↓
LET LET LET
 ↓
Yacc/Bison
 ↓
Match grammar
 ↓
Valid variable
```

For an input that does not match the grammar:

```text
Invalid input
 ↓
Lex/Flex
 ↓
Token sequence
 ↓
Yacc/Bison
 ↓
Grammar mismatch
 ↓
Invalid variable
```

---

## Error Handling

The generated parser contains the following error function:

```c
int yyerror(const char *s)
{
    printf("Invalid variable\n");
    exit(0);
}
```

Therefore, when the parser encounters invalid input, it displays:

```text
Invalid variable
```

The main function displays:

```text
Enter the variable:
```

before calling `yyparse()`. If parsing succeeds, it displays:

```text
Valid variable
```



---

## Compilation and Execution

### Step 1 – Generate the Yacc/Bison Parser

```bash
bison -d valvar.y
```

This generates:

```text
valvar.tab.c
valvar.tab.h
```

### Step 2 – Generate the Lex/Flex Scanner

```bash
flex valvar.l
```

This generates:

```text
lex.yy.c
```

### Step 3 – Compile

```bash
gcc valvar.tab.c lex.yy.c -o valvar
```

### Step 4 – Run

Linux:

```bash
./valvar
```

Windows:

```bash
valvar.exe
```

## Lex vs Yacc

| Lex/Flex                          | Yacc/Bison                                           |
| --------------------------------- | ---------------------------------------------------- |
| Performs lexical analysis         | Performs syntax analysis                             |
| Recognizes letters/digits         | Validates their arrangement                          |
| Produces `LET` and `DIG` tokens   | Uses `variable` and `var` grammar                    |
| Generates `lex.yy.c`              | Generates `valvar.tab.c`                             |
| Answers **"What token is this?"** | Answers **"Does this sequence follow the grammar?"** |

## Result

The Lex and Yacc program successfully validates variables according to the grammar defined in `valvar.y`.

For example:


as demonstrated by the experiment output.

## Conclusion

Thus, a **variable validation program using Lex/Flex and Yacc/Bison** was successfully implemented. Lex identifies letters and digits as tokens, while Yacc checks whether the resulting token sequence satisfies the specified variable grammar.
