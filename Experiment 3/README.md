# Experiment 3 – Arithmetic Expression Validation using Lex and Yacc

## Aim

To design and implement a **Lex and Yacc program** to recognize and validate arithmetic expressions.

## Objective

* Use **Lex/Flex** to identify tokens such as identifiers and digits.
* Use **Yacc/Bison** to check the syntax of arithmetic expressions.
* Recognize arithmetic operators and parentheses.
* Accept valid expressions and reject invalid expressions.

## Software Requirements

* Lex/Flex
* Yacc/Bison
* GCC Compiler
* C Programming Environment

## Files

| File             | Description                   |
| ---------------- | ----------------------------- |
| `art_expr.l`     | Lex/Flex source file          |
| `art_expr.y`     | Yacc/Bison grammar file       |
| `lex.yy(2).c`    | Generated Lex/Flex C file     |
| `art_expr.tab.c` | Generated Yacc/Bison C parser |
| `art_expr.tab.h` | Generated header file         |
| `art_expr.exe`   | Executable file               |
| `output(2).txt`  | Sample output                 |

## Description

This experiment combines **Lex/Flex** and **Yacc/Bison**.

### Lex/Flex

Lex performs lexical analysis and converts the input expression into tokens.

The scanner recognizes:

* `ID` – Identifier
* `DIG` – Digit
* `+`
* `-`
* `*`
* `/`
* `(`
* `)`

The generated scanner returns `ID` for identifiers and `DIG` for digits, while arithmetic operators and parentheses are returned as individual characters. 

### Yacc/Bison

Yacc receives the tokens generated by Lex and checks whether they follow the arithmetic-expression grammar.

The parser defines `ID`, `DIG`, and `UMINUS` tokens and supports `+`, `-`, `*`, `/`, `(` and `)`. 

## Grammar

The grammar implemented in the experiment can be represented as:

```text
stmt → expn

expn → expn + expn
     | expn - expn
     | expn * expn
     | expn / expn
     | ( expn )
     | ID
     | DIG
     | - expn
```

The generated Bison parser contains the corresponding `stmt` and `expn` grammar rules. 

## Token Description

| Token    | Meaning                   | Example         |
| -------- | ------------------------- | --------------- |
| `ID`     | Identifier                | `a`, `x`, `abc` |
| `DIG`    | Digit/number              | `5`, `10`       |
| `+`      | Addition                  | `a+b`           |
| `-`      | Subtraction / unary minus | `a-b`, `-a`     |
| `*`      | Multiplication            | `a*b`           |
| `/`      | Division                  | `a/b`           |
| `(`      | Opening parenthesis       | `(a+b)`         |
| `)`      | Closing parenthesis       | `(a+b)`         |
| `UMINUS` | Unary minus               | `-a`            |

## Working

The overall flow of the program is:

```text
Input Expression
       ↓
   Lex / Flex
       ↓
     Tokens
       ↓
  Yacc / Bison
       ↓
 Grammar Checking
       ↓
 ┌─────┴─────┐
 ↓           ↓
Valid       Invalid
Expression  Expression
```

### Example

For the input:

```text
a+10
```

Lex identifies:

```text
a  → ID
+  → +
10 → DIG
```

Yacc receives:

```text
ID + DIG
```

The sequence matches the expression grammar, so it is accepted.

## Invalid Expression

The provided experiment output shows:

```text
Enter the Expression:a=b
Invalid Expression
```



The expression is rejected because `=` is not one of the operators supported by the grammar.

The supported arithmetic operators are:

```text
+
-
*
/
```

## Unary Minus

The program distinguishes between normal subtraction and unary minus.

### Binary minus

```text
a-b
```

Here `-` operates between two expressions.

### Unary minus

```text
-a
```

Here `-` operates on a single expression.

The generated Bison header defines `UMINUS` as a separate token. 

## Compilation and Execution

### 1. Generate Yacc/Bison Parser

```bash
bison -d art_expr.y
```

This generates:

```text
art_expr.tab.c
art_expr.tab.h
```

### 2. Generate Lex/Flex Scanner

```bash
flex art_expr.l
```

This generates:

```text
lex.yy.c
```

### 3. Compile

```bash
gcc art_expr.tab.c lex.yy.c -o art_expr
```

### 4. Run

Linux:

```bash
./art_expr
```

Windows:

```bash
art_expr.exe
```

Enter an arithmetic expression when prompted.

## Example Execution

### Valid

```text
Enter the Expression:a+b
valid Expression
```

### Invalid

```text
Enter the Expression:a=b
Invalid Expression
```

The second result is confirmed by the provided experiment output. 

## Lex vs Yacc

| Lex/Flex                          | Yacc/Bison                   |
| --------------------------------- | ---------------------------- |
| Performs lexical analysis         | Performs syntax analysis     |
| Identifies tokens                 | Checks grammar               |
| Uses patterns/regular expressions | Uses grammar rules           |
| Produces `lex.yy.c`               | Produces `art_expr.tab.c`    |
| Answers **"What is this?"**       | Answers **"Is this valid?"** |

## Result

The Lex and Yacc program successfully recognizes and validates arithmetic expressions containing identifiers, digits, arithmetic operators, parentheses, and unary minus.

## Conclusion

Thus, an **arithmetic expression validator using Lex/Flex and Yacc/Bison** was successfully implemented. Lex performs tokenization, and Yacc checks whether the resulting tokens form a valid arithmetic expression according to the specified grammar.
