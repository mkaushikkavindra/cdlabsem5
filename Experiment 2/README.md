# Experiment 2 – Lexical Analyzer for C Tokens

## Aim

To design and implement a **Lex/Flex program** that performs lexical analysis of a C program and identifies different types of tokens such as keywords, identifiers, numbers, operators, delimiters, preprocessor directives, and header files.

---

## Objective

The lexical analyzer recognizes the following components of a C source program:

* Preprocessor directives
* Header files
* Keywords
* Identifiers
* Numbers
* Operators
* Delimiters
* End of file

---

## Files

| File            | Description                 |
| --------------- | --------------------------- |
| `lexer.l`       | Lex/Flex source program     |
| `iplex.c`       | C source file used as input |
| `lex.yy.c`      | C source generated by Flex  |
| `lexer.exe`     | Compiled executable         |
| `output(1).txt` | Sample execution output     |

## Input

The input C program used in this experiment is:

```c
#include<stdio.h>

void main()
{
    int x;
    x = 10;
}
```

The input source file is `iplex.c`.

## Tokens Recognized

The program classifies the input into the following token types.

| Token Type             | Example                 |
| ---------------------- | ----------------------- |
| Preprocessor Directive | `#include`              |
| Header File            | `<stdio.h>`             |
| Keyword                | `void`, `int`           |
| Identifier             | `main`, `x`             |
| Number                 | `10`                    |
| Operator               | `=`                     |
| Delimiter              | `(`, `)`, `{`, `}`, `;` |

## Working

The basic working of the lexical analyzer is:

```text
C Source Program
       ↓
     Flex
       ↓
Lexical Analyzer
       ↓
Read input character by character
       ↓
Match Lex/Flex patterns
       ↓
Classify tokens
       ↓
Display token type and value
```

The `lexer.l` file contains the patterns and actions used by Flex. The generated `lex.yy.c` contains the scanner implementation produced by Flex.

### Step 1 – Generate the Lexical Analyzer

## Important Concepts

### Lex/Flex

Lex/Flex is used to generate a **lexical analyzer** from a set of regular-expression-based rules.

The programmer specifies:

```text
Pattern → Action
```

For example:

```text
Identifier pattern → print "Identifier"
Number pattern     → print "Number"
```

Flex then generates the C scanner automatically.

---

### Lexical Analyzer

A lexical analyzer is the first major phase of a compiler.

It reads the source program and converts the sequence of characters into meaningful **tokens**.

For example:

```c
int x = 10;
```

becomes:

```text
Keyword    → int
Identifier → x
Operator   → =
Number     → 10
Delimiter  → ;
```

---

### Token

A token is a meaningful unit recognized by the lexical analyzer.

Examples include:

```text
Keyword
Identifier
Number
Operator
Delimiter
```

---

### Regular Expression

Lex/Flex uses regular expressions to describe token patterns.

For example, an identifier can generally be described using a pattern that begins with a letter or underscore and is followed by letters, digits, or underscores.
