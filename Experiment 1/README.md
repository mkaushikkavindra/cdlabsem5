# Experiment 1 – Lexical Analyzer and Symbol Table

## Aim

To design and implement a **Lex/Flex program** that performs lexical analysis of a C source file and constructs a **symbol table** containing the identifiers encountered in the input.

---

## Objective

The program identifies and displays the following lexical elements from a C source program:

* Identifiers
* Constants
* Operators
* Comments
* Symbol table entries

The program uses **Lex/Flex regular expressions** to recognize different types of tokens.

## Input

The input C program used for the experiment is:

```c
int a = 10; // sum variable
b = a + 5;
```

This input contains:

* Identifiers: `int`, `a`, `b`
* Constants: `10`, `5`
* Operators: `=`, `+`
* Comment: `// sum variable`

## Lex/Flex Program

The main Lex/Flex source file is `symtab.l`.

It defines two important regular expressions:

```lex
DIGIT   [0-9]
ID      [a-zA-Z_][a-zA-Z0-9_]*
```

### Token Rules

| Pattern         | Token Recognized    |
| --------------- | ------------------- |
| `/* ... */`     | Multi-line comment  |
| `//.*`          | Single-line comment |
| `{ID}`          | Identifier          |
| `{DIGIT}+`      | Constant            |
| `+ - * / = < >` | Operator            |
| `[ \t\n]`       | Whitespace          |
| `.`             | Other characters    |

Whenever an identifier is found, it is passed to the `insert()` function.

## Symbol Table

The program maintains a symbol table using the following structure:

```c
struct symtab {
    char name[30];
    int type;
} symtab[100];
```

The table can store up to **100 entries**.

The variable `sc` keeps track of the current number of entries.

### `lookup()` Function

The `lookup()` function checks whether an identifier is already present in the symbol table.

```c
int lookup(char *s)
{
    int i;

    for(i = 0; i < sc; i++)
        if(strcmp(symtab[i].name, s) == 0)
            return i;

    return -1;
}
```

If the identifier exists, its position is returned. Otherwise, `-1` is returned.

### `insert()` Function

The `insert()` function adds an identifier only if it is not already present.

```c
void insert(char *s)
{
    if(lookup(s) == -1)
    {
        strcpy(symtab[sc].name, s);
        symtab[sc].type = 1;
        sc++;
    }
}
```

Therefore, repeated identifiers are **not duplicated** in the symbol table.

## Working

The overall flow of the experiment is:

```text
C Source File
     ↓
   Flex
     ↓
Lexical Analysis
     ↓
Identify Tokens
     ↓
┌───────────────┐
│ Identifier    │ → Insert into Symbol Table
│ Constant      │
│ Operator      │
│ Comment       │
└───────────────┘
     ↓
Display Symbol Table
```

### Step-by-Step Example

For the input:

```c
int a = 10; // sum variable
b = a + 5;
```

Flex scans the input from left to right.

#### 1. `int`

Recognized as an identifier by the current Lex rule:

```text
Identifier : int
```

It is inserted into the symbol table.

#### 2. `a`

Recognized as an identifier:

```text
Identifier : a
```

It is inserted into the symbol table.

#### 3. `=`

Recognized as an operator:

```text
Operator : =
```

#### 4. `10`

Recognized as a constant:

```text
Constant : 10
```

#### 5. `// sum variable`

Recognized as a comment:

```text
Comment : // sum variable
```

#### 6. `b`

Recognized as an identifier and inserted into the symbol table.

#### 7. `=`

Recognized as an operator.

#### 8. `a`

Recognized as an identifier.

Since `a` already exists in the symbol table, it is **not inserted again**.

#### 9. `+`

Recognized as an operator.

#### 10. `5`

Recognized as a constant.

## Important Concepts

### Lex/Flex

**Lex** is a tool used to generate lexical analyzers. **Flex** is a commonly used implementation of Lex.

It takes token patterns and corresponding actions and generates a C scanner.

### Lexical Analyzer

A lexical analyzer reads source code and breaks it into meaningful units called **tokens**.

For example:

```c
a = 10;
```

can be recognized as:

```text
Identifier → a
Operator   → =
Constant   → 10
```

### Regular Expression

Regular expressions describe patterns for recognizing tokens.

For example:

```lex
[a-zA-Z_][a-zA-Z0-9_]*
```

recognizes identifiers such as:

```text
a
sum
total1
_variable
```

### Symbol Table

A symbol table is a data structure used by a compiler to store information about identifiers encountered during compilation.

In this experiment, the table stores the identifier name and a `type` field.
